# Equity Research 命名决策与迁移计划

日期：2026-09-20。状态：显示层已于 2026-09-20 部署，验收通过。既有技术路径和调度标识保留兼容。

## 决策

停止把开发阶段编号用作系统名称，也不再新增 Phase 5R-C10、Phase 6 等项目级编号。面向用户的固定名称采用 **Equity Research**（股票研究）；工作区和 Git 仓库继续使用 `equity`。

已有 `phase5r` 路径、导入名、schema、调度任务和状态键作为兼容标识保留。它们不表示当前成熟度、投资表现、风险等级或用户需要理解的工作阶段。历史档案保留原名以便追溯。

本文件规定后续命名；既有运行配置和权限仍由当前 active state/config 管理。命名迁移不改变投资策略、阈值、通知资格或数据源。

## 迁移前核实的来源

1. 截图显示 `Phase 5R Equity Bri…`。生产 `07_automation/email_delivery/phase5r_email_config.local.json:7` 的 `sender_name` 为 `Phase 5R Equity Brief`。迁移前发送器 `09_scripts/phase5r/send_phase5r_daily_email.py:405` 将该字段写入邮件 `From` 显示名。截图与此名称一致；末尾省略号是显示截断，不是配置的一部分。

3. 已提交的邮件配置模板使用 `AI Investment Research Assistant`，实际本地配置使用 `Phase 5R Equity Brief`，说明目前没有单一显示名称来源。本地配置未纳入 Git，不能仅凭提交历史确认是谁、何时设置了该显示名。
4. 归档 `11_archive/phase5r_retired_20260831/00_project_control/phase0c_reframe_plan.md:3–9` 自记运行时间为 2026-07-08，把 Phase 5R 描述为重新划定范围的 realtime stock picker。该文件已包含于当前可见 Git 最早提交 `e719060`（2026-07-24）；文档自记日期与 Git 首次记录日期不能混为一谈，也不能据此证明该名称第一次产生的精确时间。
5. 同一档案提到旧 Phase 5A/5B 邮件预检；后续 Phase 5R-A 为静态选股脚手架，B/B2 为市场数据，C1/C2/C3 为简报/发送/流程，C4–C9 延伸至持仓研究、风险和账户状态，D1–D3 为调度。它们是历史交付编号，不是稳定的产品版本体系。
6. 未找到明确规定 `R = ...` 的正式定义。上下文包含 Reframe 和 realtime，但不能擅自把任一词认定为 R 的官方展开。也未找到统一规定字母、数字和扩展后缀如何递增的项目级命名规范。

以上档案仅用于命名溯源，里面旧的执行指令和范围限制不因本次阅读而重新生效。

## 新命名规则

| 对象 | 规则 | 示例 |
|---|---|---|
| 系统和发件人显示名 | 固定使用 Equity Research | `Equity Research` |
| 用户报告 | 功能名称 + 日期；内容以中文为主 | `每日研究简报｜2026-09-20`、`持仓复核｜2026-09-20` |
| 普通邮件主题 | 固定品牌前缀 + 当前研究结论 + ET 周期日期 | `[Equity] 长期研究待复核｜2026-09-20` |
| 更正/应请求复核 | 保留实际消息类别，与正常消息区分 | `[Equity 更正版] …`、`[Equity 应请求复核] …` |
| 当前状态页面 | 固定功能名称，生成时间放正文 | `Equity Research — 运行状态` |
| 公司研究 | ticker + 研究主题 + as-of 日期 | `NVDA｜长期研究｜2026-09-20` |
| 新功能模块 | 稳定 snake_case 功能名，默认不编码开发顺序 | `official_news`、`market_regime`、`company_research`、`valuation`、`portfolio_risk`、`reporting`、`operations` |
| 改进任务 | 日期 + 明确结果；进度用状态字段 | `2026-09-20 官方新闻稳定性改进`；状态：计划中/实施中/验证中/已上线 |
| 研究/运行政策版本 | 生效日期 + 当日修订号 | `2026-09-20.1` |
| 数据协议版本 | 仅在需要区分协议兼容性时使用 v1/v2；为已有消费者保留兼容 | `news_events_v1`；旧 schema 不因改显示名而改写 |
| 部署版本 | Git commit 标识 | 使用已部署 commit，不另造 Phase 号 |
| 历史文档 | 保持原文件名与当时标题，索引标为历史 | `Phase 5R-C2` 仅作为历史引用 |

跨模块脚本优先使用动作 + 对象，例如 `refresh_official_news.py`。维护已有模块时继续遵循其当前导入和文件约定，避免制造一半新名、一半旧名但没有映射的接口。实际迁移路径要单独列出，不凭命名规则自动搬动已有文件。

## 迁移顺序

### 先统一用户看到的名称

- 将发件人显示名、邮件主题前缀和报告品牌集中到一处可提交的非敏感显示配置，例如 `01_policies/equity_display_names.json`。
- 当前邮件发送器从该非敏感配置取得显示名称，避免品牌继续依赖含 SMTP 设置的私有文件；SMTP 连接、收件人、凭据和既有配送配置不随命名调整而修改。旧 `sender_name` 可暂留兼容，但明确统一的读取优先级。
- 更新普通、更正、应请求复核及旧 brief 兼容分支；对应更新当前配送政策与预览。
- 更新生成中的每日简报、持仓报告、长期研究、状态报告和桌面提示标题。源模板一起改，避免下次刷新恢复旧名。
- 更新 README 和当前文档入口；历史档案、既有已发送邮件和审计证据不重写。

### 再统一后续开发用语

- 新任务、模块和文档采用上述功能命名。
- 建立一个简短旧名对照表：B2→市场数据，C9→组合与风险，daily→每日研究流程，D1–D3→历史调度，SHADOW→研究评估环境。映射只解释含义，不恢复已退役组件。
- 进度用“计划中/验证中/已上线”等状态表达，不通过增加字母来表达修复、批准或上线。

### 技术标识按实际维护需要迁移

本轮计划不安排全仓库替换 `phase5r`。只有重构某个模块确有收益时，才单独迁移其脚本与导入，并核验调用者。launchd label、环境变量、schema、状态文件、配送去重键和封存证据路径须有兼容与回滚方案，不能随显示名称一起全局替换。

## 验收与回滚

- 普通、更正和应请求复核的本地邮件预览均显示新名称，三个消息类别仍可区分。
- 发件人地址、收件人、发送窗口、去重规则、Message-ID 规则和更正/复核授权逻辑保持既有行为。切换名称不应使同一周期被重复发送。
- 同一输入在改名前后的研究结果、现金/持仓/成交原始记录与策略参数一致；差异应限于显示文本及明确列出的展示元数据。
- 新生成的当前报告标题不再把 Phase 5R 当品牌；源引用、内部路径、schema 和历史标题中的保留标识属于兼容项。
- 用本地渲染与针对配送兼容性的现有测试验证；命名验证本身不触发真实邮件。
- 部署仍走 authoring → GitHub → runtime，保留运行证据。出现问题时恢复显示配置或代码提交，不清空调度/配送历史。

## 实施规则与旧名对照

显示名称的唯一运行来源是 `01_policies/equity_display_names.json`，由 `09_scripts/phase5r/equity_naming.py` 校验并提供给发送器、渲染器、报告和桌面提示。私有邮件配置中的旧 `sender_name` 字段保留兼容校验，但不再决定发件人显示名。它与新的实际显示名称不同是有意保留的兼容行为。

| 旧内部标识 | 对应功能 / 状态 |
|---|---|
| B2 | 行情采集与质量检查 |
| C9 / C9B | 组合风险、账户与人工成交复核 |
| daily | 当前每日研究及通知流程 |
| D1–D3 | 已退役的历史调度；当前使用 dailyrefresh/dailydecision |
| SHADOW | 独立研究评估环境 |

本次修改显示配置、生成器、当前文档入口和邮件配置模板。策略计算、schema、导入名、launchd label、状态和去重键保持原有技术身份。历史文档、已发邮件、封存评估与成交证据保留当时标题。
