本计划把当前研究与邮件流程连接到一个手机和 Mac 共用的私人网页。用户查看当前方案，在 Chase 手动操作后填写表单；后台校验反馈、更新正式账户记录、重算风险与数量，并在需要时交给现有研究流程复审。以完成条件推进 phases，具体范围和顺序可随使用反馈调整。

## 已确定的产品方向

- 以表单交互为主。第一版不嵌入聊天，不新增 AI API 或券商接口；沿用现有公共行情和 SEC 采集。
- 首页回答今天做什么、什么条件下做、操作后如何登记。动作包括条件买入、减仓、退出、保护、持有、观察和暂不行动。
- 手机与 Mac 使用同一份生产状态。日 K 线、执行反馈、账户核对、历史和明确回执属于第一版目标。
- 研究决策、人工成交、挂单和规划假设分别记录。既有邮件中的假设成交情景不能成为实际账户记录。
- 提交表单只记录用户报告的操作。Chase 中的交易由用户执行；金额、费用和当前资金可用性保留来源及确认状态。
- 现有账户配置、策略和邮件发送政策继续适用。新增页面或图表不会自行改变这些规则。

### Phase 0 定义数据和操作契约

把计划、订单、成交和账户观察分开建模。每个反馈绑定稳定记录 ID、所查看的计划版本、账户版本、发生时间及登记时间。大致成交时间允许带精度标记；用于正式对账的股数、成交金额和费用必须明确，未知字段不能默认为零。

表单根据状态展开：未操作、已挂单、部分成交、全部成交、已撤单、账户核对。成交表单接受单价或总金额，明确总金额是成交金额还是净到账；部分成交保留剩余订单。订单撤销与历史成交分别记录。新建成交不自动证明完整挂单列表已核对；账户核对另行记录其时间与完整性。

规定方案字段的来源、优先顺序和有效期。卡片展示动作、股数、价格条件、适用交易日和时段、跳过条件、理由及来源。失效或缺少依据的数值不作为当前有效方案继续展示。条件结构化须经现有计划校验，不能从自由文本提取数值后直接产生新增交易建议。

使用隔离测试数据确定预期结果，覆盖首次买入、同股连续成交、最后一个持仓清仓、部分成交后撤单、时间顺序不明、重复提交以及提交期间定时任务更新账户。

### Phase 1 查看和试填页面

完成四个入口：今日方案、股票详情、我的账户、反馈与历史。桌面展示信息关系，手机优先让用户快速看清动作并完成表单。使用真实只读生产产物核对展示，同时用明确标记的隔离预演验证提交体验。

状态栏显示研究生成时间、行情对应交易日、账户最后核对时间和待处理反馈。网页通过后台发布的完整快照读取一致版本，避免将重算到一半的账户和方案拼在一起。刚过期的方案根据当前时间失效，不等待次日批处理。第一版试填记录明确标记为演示记录。

完成页面与表单的实际浏览器检查，包括窄屏、输入错误、空数据、加载失败、离线提示、历史方案和待核对记录。计划首次开发时再确定前端和后台框架，本计划不锁定依赖版本。

### Phase 2 正式写入和完整重算

后台采用限定操作的统一入口，协调已有运行锁、账户校验和维护中的 writers。记录请求与前后状态哈希，提交前检查账户是否已经变化；过时页面需要展示差异，让用户核对，不能覆盖较新的记录。每个请求重试返回原处理结果，避免重复应用成交。

扩展现有账户及成交流程，支持新标的、清仓、全现金和连续部分成交。成本、费用、外部入金以及估算现金保留各自依据。对可用或结算资金未知的情况继续保留原门槛，不将记录的卖出收入直接视为已核验可用于新交易的资金。

多文件写入需要准备回执、保留原文件、写后核验和可恢复状态；单个文件原子替换不能证明整个账户更新原子完成。记录保存、账户应用、研究重算和分析复审分别报告状态。已经接纳的人工事实不因后续公共行情失败被丢弃；停止发布依赖旧账户的数量方案，并保留精确失败原因和待恢复任务。

在提交完成后触发合适的账户重算及既有完整无发送刷新；需要新判断时进入复审队列。任意后台重算不等于分析师已完成新建议。正常邮件仍由既有发送入口和政策负责。

此 phase 的检查必须看最终持仓、现金、挂单、计划状态、决策 JSON、页面和文本 HTML 产物，确认其使用相同账户版本。重点检查旧方案是否仍显示旧数量、相同成交是否被重复应用、公共数据失败是否误撤销事实。

### Phase 3 手机访问和日 K 线

部署优先采用现有 Mac 后台与私人 HTTPS 访问，具体访问服务在实施时核验。需要用户设备身份和访问限制；私人账户不能通过未认证公共网页读取或写入。Mac 停机或离线时显示服务不可用及缓存日期，不显示提交成功。服务重启后的未完成请求要能恢复。

复用现有日线 OHLCV 和来源，校验缓存与行情快照一致。图表注明交易日、数据延迟和复权口径，叠加仍有效的计划线、复核线和用户成交点。成交点以用户记录为来源，和公共行情分开。扩大历史范围或新增指标时记录数据需求，盘中价格及分钟线留作后续独立选择。

关联邮件保留的原始方案版本。用户从旧邮件进入时可以看到当时方案与当前变化；当前页面更新不能回写已发送邮件历史。继续区分实际持仓与假设全部成交的规划情景。

在真实手机和 Mac 上验收查看、填写、回执、同步、重复请求、过期页面、服务重启和未授权访问。手机无法测试时，报告该项未验证，不宣称 Phase 3 完成。

### Phase 4 根据使用反馈调整

先观察每次登记的步骤和常见缺项，再决定增加默认值、快捷按钮、历史筛选或 CSV 导入。默认值只能来自已知记录；费用未知不能默认确认零，订单没有反馈不能默认成交。

复审请求可以先由现有分析师任务消费，展示接收、处理和完成状态，不承诺即时分析。账户纠错通过带原因的更正记录和受控恢复实现，保留历史，禁止无审计覆盖旧成交。只有所需入金、费用、分红及公司行动记录齐备时才扩展真实投资表现计算。

## 调整范围和顺序的规则

每完成一个 phase，检查真实页面和完整路径，将下一 phase 拆成必须、可后移、待决定三个列表。已通过的验收保留；新需求影响既有结果时，重开对应项并注明原因。使用同一计划文件维护进度，避免出现互相矛盾的第二份路线图。

| 变化 | 调整方式 | 必须重验的内容 |
| --- | --- | --- |
| 表单名称、字段顺序、默认日期或卡片布局 | 可在当前 phase 内调整 | 移动端填写、字段语义、保存回读 |
| 手机访问比图表更急 | 提前 Phase 3 的访问工作，图表随后完成 | 认证、真实手机连通、断线与重复提交 |
| 对账难度高于预期 | 保留查看和隔离试填，先解决写入问题 | 页面明确预演状态，生产账户未被误改 |
| 新增反馈类型、账户字段或纠错规则 | 修改契约并更新迁移与恢复方案 | 所有消费方、历史兼容、重复与并发处理 |
| 需要实时价格、分钟线或 Mac 关机仍可提交 | 单列数据或部署扩展，重新评估服务、成本与同步 | 新数据权限、延迟、账户唯一来源、离线行为 |
| 改变策略、风险阈值、账户权威来源或邮件发送政策 | 单列为明确的产品和架构决定，确认用户方向后推进 | 对应政策和全部受影响路径 |

布局、字段顺序和实施内部选择可常规调整。需要新增付费服务、公开账户访问、迁移正式账户来源或改变投资策略的事项，应先给出具体方案和影响再确认。用户已明确要求的调整不重复索取批准。
