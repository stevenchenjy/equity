# Issuer-news review continuity

The seven-day official-news window controls admission of fresh headlines. It is not a deadline that resolves research. Same-root long-horizon report generation and decision composition admit only verified substantive issuer announcements from that current window into `04_research/company_research/issuer_news_review_queue.local.jsonl`. The private append-only hash chain retains the stable event content, its hash, source identity, source response hash and verified observation time. Unchanged polls do not add entries. Older feed archives are not automatically promoted into a new review backlog.

Long-horizon reports, decision composition and publication validation merge this queue with the current verified feed. A pending event remains visible when it leaves the window or when its source subsequently fails. Previously triggered reassessment also survives an unrelated later thesis revision. Source freshness remains a separate coverage gate; retaining a headline does not claim that its source is currently healthy or that the article has been researched.

Resolve an event through an authored thesis revision containing `reviewed_news_events`: the exact `stable_news_event` payload and canonical `event_sha256`, an explicit assessment, and `review_scope: issuer_headline_triage`. Admission can validate an aged event against its retained source receipt. A current verified correction requires the corrected payload. Producer phases retain the acknowledgment linked to its validated thesis review ID and record hash. A wrong hash cannot clear a pending event, and revised issuer content reopens review. Merely refreshing data, changing a review date, or omitting a prior event is not acknowledgment.

Publication validation and preview runs with different input/output roots are read-only. Queue corruption blocks publication instead of being interpreted as an empty queue. The queue is included in the publication input hashes and excluded from Git; preserve it with the other private continuity ledgers during runtime backup or migration. Notification semantics use retained event identity and maintained review state, so ordinary lookback-window ageing and fetch timestamps do not create notification changes.

This queue preserves headline triage only. It neither establishes a supported business case nor authorizes an investment action. Its initial coverage begins with verified events in the admission window at deployment; it does not establish completeness for historical news before that window.
