# Equity Research Dashboard Phase 0 和 Phase 1 契约

生效范围：2026 年 9 月 30 日开始的 Phase 0 和 Phase 1 实施。用户要求完成 Phase 1 后停止。正式账户写入、生产部署、私人手机联网和 K 线属于后续 phases。

## 用户可观察的结果

用户在本地网页查看同一份已发布的研究、账户、持仓和维护计划，看到行情交易日、研究生成时间、账户更新时间和计划复审期限。用户填写执行反馈并收到明确的演示回执，在同一浏览器重新加载后仍能查看历史。

正式研究与账户来自生产 checkout；演示反馈只在浏览器独立存储。保存演示记录不证明用户实际成交、账户已更新、研究已重算或邮件已发送。

## 数据入口和输出

| 数据 | 权威来源和读取规则 | 用户看到的输出 |
| --- | --- | --- |
| 研究决定 | 生产 `04_research/company_research/daily_decision.json` | 今日方案、观察名单、研究时间 |
| 账户和持仓 | 生产账户 JSON、持仓 CSV；须与决策内的输入指纹、数量及现金一致 | 账户估值、记录现金、持仓；结算资金核验独立显示 |
| 当前计划 | 决策中的版本化 `plan_continuity`，须匹配正式计划输入指纹 | 计划版本、状态、复审时间、完整原文和来源 |
| 公共价格 | 生产行情 CSV；核对持仓价格和交易日与决策一致 | 明确标注非实时的参考收盘 |
| 订单观察 | 生产 `current_open_orders.local.json`，记录观察时间、完整性和新鲜度 | 上次核对时的订单，不推断此刻券商状态 |
| 演示反馈 | 浏览器 `localStorage` 的 `equity-dashboard-demo-v1`，最多 200 条 | 试填回执、待补全项、独立演示历史 |

后台固定读取 `/Users/messssi/LocalRuntime/equity`，服务绑定 `127.0.0.1`。现有 runtime 锁的共享读取防止与更新交错；发布输入指纹和读取前后字节检查进一步确认一致性。代码不导入可能持久化状态的研究模块，也不启动 pipeline、sender 或账户 writer。

缺少或不匹配的发布指纹、持仓数量、现金、行情、动态总值或者读取期间的变化，会让快照接口返回不可用。页面说明原因，旧快照保留时明确标注，暂停当前数量方案。读取失败不退回开发目录、例子、历史归档或假设成交情景。

## 页面与状态规则

导航为今日方案、我的账户、填写反馈、记录历史。股票详情从计划进入。今日方案以列表展示，不制造每日必买的候选；没有有效新增方案时照实展示。每分钟重新读取已发布快照；更新视图只重新读取，不启动研究。

计划以复审时间、有效期和时间退出期限中的最早时间判断。达到期限立即变为需复审，清除当前可用数量和订单草案；旧原文仅在历史依据中回看。没有期限的计划标记依据待核对。不同研究日期标记过期研究，不能自动续期或将旧收盘当实时价格。

界面使用白底、深色文字和深绿色操作按钮，琥珀色表示演示和待复审。桌面保留侧导航和左方案右表单；窄屏改为底部导航与纵向表单。表单支持键盘标签、错误提示和减少动画设置。设计参考中的金额是示意，实际页面只显示已核对的生产数值。

## 表单字段和校验

| 反馈状态 | 字段 | 保存为信息齐全的条件 |
| --- | --- | --- |
| 未操作 | 标的、日期、大致时间、可选备注 | 标的和日期有效；不产生订单或成交 |
| 已挂单 | 标的、方向、数量、订单类型、限价或触发价、有效期、日期时间 | 数量及对应价格明确；保留为挂单，剥离上一次试填的成交金额 |
| 部分成交 | 标的、方向、实际成交股数、单价或金额、金额口径、费用、剩余挂单股数、日期时间 | 数量金额费用和剩余量明确；不假定剩余已成交 |
| 全部成交 | 标的、方向、实际股数、单价或金额、金额口径、费用、日期时间 | 数量金额费用明确 |
| 已撤单 | 标的、对应订单、撤单日期时间、此前是否部分成交 | 对应订单明确；若有先前部分成交，保留该依赖待另行核对 |
| 账户核对 | 完整持仓列表、现金、完整挂单核对标记、日期时间 | 持仓和现金有效，完整订单核对明确；空持仓列表允许表示全现金 |

股票代码有效且账户列表不重复；现有 workflow 使用整股，数量须为正整数。金额须有限且为正，费用和现金可以为零。确认零费用必须显式输入；未知费用保留空值。日期须有效且不晚于当前美东日期。大致时间可不填；填写时按 ET 记录并标记 approximate，未填时为 date_only。

金额口径区分每股单价、未扣费总金额、含费用的实际扣款或到账。费用未知的净额不能推出确认的成交单价。缺少必需事实仍可保存为演示待补全；负数、非整股或错误日期则提示修正后再保存。

## 演示记录和状态流转

可执行类型定义与校验位于 `10_dashboard/src/domain.ts`。每条演示记录保存 `schema_version`、稳定 `id`、`recorded_at`、`production_effect=false`、`stage`、`missing`、查看的 `snapshot_id` 和 `account_version`、可关联的计划 ID 版本哈希、事件时间精度及表单内容。

状态流转是填写、字段校验、保存演示记录、信息齐全或待补全。保存后回执明确显示实际账户未更新和研究未重算。成功保存的相同表单在未编辑前不重复登记，记录 ID 重放也不新增历史。改变反馈类型会清除不适用的成交或订单字段。

浏览器存储失败或损坏时明确提示，不显示保存成功，也不自动覆盖损坏内容。演示记录限本地浏览器，不跨手机或 Mac 同步；跨设备账户状态和正式写入在后续 phase 完成。历史清除仅涉及演示空间，并要求页面内确认。

## Phase 1 的边界和后续接点

后台仅有读取快照与静态页面入口；写请求返回 405。限制 Host、Origin、跨站读取和静态文件路径，页面资源来自本地，不调用新的外部 AI 服务或提交私人账户到第三方。

Phase 2 接入时，演示记录不能自动升级为正式成交。需要新的受控写入入口、生产账户版本复核、对账、完整重算和回执。Phase 1 定义了字段与关联版本，为后续使用提供接口依据，没有执行这些写入。

## 验收证据

2026-09-30 ET：Phase 0 和 Phase 1 已完成，本地构建、18 项测试及实际浏览器验收通过；完成后按用户要求停止。分阶段计划中的完成记录与本契约保持一致。

Phase 0 验收检查契约、类型定义、来源与写入边界、典型反馈状态以及未知事实处理。Phase 1 验收检查实际浏览器页面、核心试填保存、历史刷新、有效零费用、未知费用、部分成交、挂单、撤单、全现金演示、过期计划、损坏或不可用状态以及桌面和手机尺寸布局。

生产账户输入在检查前后保留哈希，验证 dashboard 未改动正式账户。真实手机联网、券商订单、正式账户写入、研究触发及生产 dashboard 部署不属于本次完成证据。
